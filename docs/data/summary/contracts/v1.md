# 契约重构 v1：表 / 实体 / 查询

> 范围：`contracts/_meta/data.{tables,entities,queries}.yaml`、`contracts/data/{storage.yaml,tables,entities,queries}`、`scripts/cmd/internal/{check,graph,contractspec}`。
> 状态：已落地；`make contract-check`、`make gen-graph-check`、`make test-tools`、`make lint-tools`、`make test-api`、`scripts/check-docs.sh` 全部通过。

---

## 1. 背景与目标

旧模型把三类信息混在一起：

- 表的继承（`extends`）在顶层，表的物理事实（`size_class`/`retention`/`partition`）在 `table` 下，存储引擎在 `storage.yaml`，三处分散；
- 实体字段的列来源靠 `snake_case(name)` 隐式推断，可空性靠 `required` 表达，计算字段无法声明，关系是独立的 `relations` 列表；
- 查询把完整 SQL 写成结构化对象，`select`、`returning` 与 `returns` 重复；索引使用靠 `index_columns` 重写列前缀，而不是引用表里已有的索引。

本次改造的目标：**让每条硬约束只有一个真相源，让脚本能验证的尽量硬校验，让 AI 不需要靠隐式规则猜。**

---

## 2. 设计决策

### 2.1 表：结构归表，物理事实归 storage

- `table.extends` 是唯一的继承入口；多父、钻石继承、环检测保持原语义。
- `engine / size_class / retention / partition` 统一登记在 `contracts/data/storage.yaml` 的 `tables` 注册表，键是 `data.tables.*`：
  ```yaml
  tables:
    data.tables.account:
      size_class: large
      retention: { unit: days, pending: 7, soft_delete: 30, hard_delete: 90 }
  ```
- checker 做双向登记：每张物理表必须有条目、条目必须指向存在的表；`engine` 必须在 `supported_engines` 且已启用；`large` 表禁止显式 `concurrently: "false"`；`partition.columns` 必须存在，`range` 必须有 `interval`。

**理由**：表契约回答“数据长什么样”，storage 回答“数据怎么存”。两者变更频率与评审人不同，混在一起会让业务评审被迫阅读物理细节。

### 2.2 实体：字段即投影，来源/校验/可空显式化

`fields` 同时承载标量字段与关系字段，二者互斥：

```yaml
- name: OwnType
  json_name: own_type
  type: string
  source: { column: data.tables.account.col.own_type }
  validation: { column: data.tables.account.col.own_type }
  description: "归属类型"

- name: Tokens
  json_name: tokens
  relationship: one_to_many
  target: data.entities.token
  join_column: data.tables.token.col.account_id
  load: lazy
  description: "账号的设备令牌"
```

- **来源**：`source.column`（数据库列）或 `source.computed`（计算/聚合），二选一。列字段必须属于 `model.tables`；computed 字段必须使用指针类型 `*T`，因为查询可能不装载它；同一列不得被两个字段引用；多表合成每张表至少被一个字段引用。
- **可空**：`type` 的 `*` 前缀与来源列 `nullable` 强制一致；`required` 已删除，避免“指针/required/列 nullable”三套真相。
- **校验**：`validation.column`（复用列规则）/ `pattern`（字符串硬正则）/ `soft`（脚本无法验证的表达式），三选一，每个标量字段必填。
- **关系**：`relationship`（原 `kind`）/ `target` / `join_column`（原 `via`）/ `load`（默认 lazy）；关系字段不写 `source`/`type`/`validation`/`mutable`/`pii`/`never_expose`/`examples`。
- **描述**：每个字段（含关系字段）必须写 `description`。
- `used_by.entities` 由关系字段反向计算，`relations` 顶层键删除。

**理由**：AI 最容易犯的错是“按名字猜列”“用业务必填替代物理可空”“把关系当成普通字段”。现在这些都有硬约束或至少强制显式声明。

### 2.3 查询：从 SQL 对象到伪 SQL 硬约束

查询不再写完整 SQL：

```yaml
- id: data.queries.account.get_account
  name: GetAccount
  kind: one
  statement: select
  targets: [ data.tables.account ]
  params:
    - { name: id, type: text, column: data.tables.account.col.id }
  returns: data.entities.account
  where:
    - { column: id, op: eq, param: id }
    - { column: deleted_at, op: is_null }
  index_ref: [ data.tables.account.pk ]
  semantics: "已软删视为不存在；按实体字段投影为账号"
```

- **目标表**：`targets[0]` 是主表；JOIN 表同时写进 `targets` 与 `joins`；写语句只能一张目标表。
- **投影**：表行/实体返回由 `returns` 推导，`return_columns` 只做裁剪；标量返回写 `expr`；统计/聚合返回写 `output_fields[].expr`。不再手写 `select`/`returning`。
- **写入**：`values` 是“列名 → 表达式”映射，insert/update 共用。
- **索引**：`index_ref` 指向 `data.tables.<t>.pk` 或 `indexes[].name`，与 `indexes[].used_by` 双向校验。
- **参数**：`params` 是唯一入参声明；所有伪 SQL 表达式里的 `@name`/`sqlc.arg`/`sqlc.narg` 都必须回落到它。
- **归属**：`module` 改名 `owner_module`，写查询必须等于 `targets[0]` 的 `owner_module`。

**理由**：`select` 与 `return_columns` 重复、`index_columns` 与表索引重复、完整 SQL 无法被脚本验证。扁平化后，checker 只校验可机械判定的引用与形态，表达式语义交给 sqlc / EXPLAIN。

## 3. SQL 子句 → 硬约束映射

| 原 SQL 子句 | 新字段 | checker 硬校验 |
|---|---|---|
| `statement` | `statement` | select/insert/update/delete |
| `from` / `into` | `targets[0]` | 表存在、非 base、写语句单表 |
| `joins[].table` | `targets` + `joins` | JOIN 表在 targets、主表不自 JOIN、ON 非空 |
| `select`（表/实体） | 由 `returns` 推导 | 实体必填字段覆盖、来源表在查询表集合内、敏感列同模块才可显式返回 |
| `select`（标量） | `expr` | 必须有且不能写 AS 别名 |
| `select ... AS alias` | `output_fields[].name/expr` | name 唯一、expr 必须有且不能写 AS 别名 |
| `columns` + `values` / `set` | `values` | 键必须是目标表列、表达式非空 |
| `returning` | 由 `returns` 推导 | 不再手写 |
| `where` / `order_by` / `limit` | 同名扁平字段 | 参数双向一致；`order_by` 只允许 `<列> ASC|DESC`；`limit` 只允许 select |
| `params` | `params` | name 唯一、nullable 与 `sqlc.narg` 严格对应、可绑定列 |
| 索引 | `index_ref` | 指向存在的索引/PK，与 `used_by` 双向一致 |
| 写归属 | `owner_module` | 等于 `targets[0]` 的 `owner_module` |

## 4. 追加收紧：params 列绑定与结构化 where

### 4.1 `params[].column`

参数可声明绑定的物理列：

```yaml
params:
  - { name: id, type: text, column: data.tables.account.col.id }
  - { name: ids, type: "[]text", column: data.tables.account.col.id }
  - { name: page_size, type: integer }   # 运行时参数，不绑列
```

规则：

- 绑定列必须属于查询的 `targets` / `joins`；
- `type` 的类型族必须与列类型族兼容（`text`↔string、`integer`↔integer、`timestamp`↔timestamp 等）；
- 数组参数（`[]text`）绑定的是元素列，用于 `in` 谓词；
- 无法绑定列的分页/批量参数保持不写 `column`。

### 4.2 结构化 `where`

`where` 的每一项可以是：

- **字符串**：软表达式，保留给函数、子查询、OR、元组比较等复杂逻辑；
- **对象**：结构化谓词，推荐用于最常见的过滤：
  ```yaml
  where:
    - { column: id, op: eq, param: id }
    - { column: deleted_at, op: is_null }
    - { column: status, op: ne, value: 3 }
    - { column: id, op: in, param: ids }
  ```

支持 `eq / ne / lt / lte / gt / gte / in / is_null / is_not_null`。checker 校验：

- `column` 存在；多表同名时必须写 `data.tables.<t>.col.<c>` 限定；
- 比较谓词二选一 `param` / `value`；`is_null`/`is_not_null` 不写二者；`in` 必须是数组参数；
- 结构化谓词引用的 `param` 必须声明 `column`，且与谓词列一致；谓词参数必须 non-nullable，可选过滤改用字符串表达式（`sqlc.narg('status') IS NULL OR status = sqlc.narg('status')`）；
- 参数/字面量类型必须与列类型族兼容；
- `is_null` 只能用于可空列。

**理由**：AI 最容易写错的是列名拼写、参数类型、可空判断。结构化谓词把这三类错误从“运行期/EXPLAIN 才发现”提前到契约检查。

## 6. 取舍与已知软区

**已选择的取舍**：

- `fields` 联合类型只能靠代码做 variant 校验；换来单一字段列表与统一遍历。
- `storage.tables` 与表契约存在 ID 重复；用双向登记防漂移。
- 查询表达式仍是伪 SQL；checker 只保证引用与形态，不解析完整语义。
- `return_columns` 仍按物理列名，而不是实体字段名/JSON 名。

**仍存在的软区（附具体漏检触发条件）**：

1. `source.computed`：只校验非空、`*T`、不引用 `@param`。`computed: "COUNT(no_such_col)"` 仍会通过；列名/表名是否正确只能靠生成器或测试发现。
2. 字符串形式的 `where`：不解析语义。`where: ["nubmer = @number"]`（列名拼错）不会被 checker 发现；需要列级硬校验时改用对象谓词 `{ column: number, op: eq, param: number }`。
3. `return_columns` 省略：表/实体返回默认排除 `never_expose` 字段，因此跨模块查询不会报“返回敏感列”，而是静默不投影；同模块需要敏感列时必须显式写 `return_columns`。
4. insert 的 `values`：不强制覆盖“非空、无默认值、非应用生成”的列。漏写 `nickname` 这类列不会在契约层报错，要等 DB 约束或测试暴露。
5. `params` 未绑列：`type` 是自由文本，`type: uuid` 与 `column` 不绑定就不会校验；能绑列的参数应写 `column`。
6. `one` 查询的 `limit: "1"`：会直接满足唯一性要求，不再要求索引；这是显式逃生口，不是索引命中证明。
7. `order_by`：只支持 `<列> ASC|DESC`；函数/表达式排序会被 `query-order-by` 拒绝，需要先扩展契约。

## 7. 后续建议

**必要**

- 当前无阻断性必要项；上述软区需要 review / 生成器测试兜底，不能仅依赖 `contract-check`。

**建议**

- 将 `values` 的 insert 列覆盖做成可选规则：对非空、无 `default`/`default_sql`、非 `generated_by: application` 的列要求出现在 `values` 中。
- 对结构化 `where` 增加 `like` / `between` / `not` 组合，但保持字符串逃生口。

**可选**

- `return_columns` 支持实体字段名或 `json_name`，降低跨层命名成本。
- 为 `storage.tables` 增加 `note` 字段，记录选择该 size_class/retention 的理由。
- 在 `contract-new` 中根据目标表自动生成参数 `column` 绑定与常用 `where` 骨架。

- **P1**：`computed` 字段强制指针类型 `*T`，使“非指针 ⇒ 列来源 ⇒ 必填覆盖”的推理闭环（`TestEntityComputedField`）。
- **P1**：`order_by` 校验限定符与裸列歧义（`TestQueryOrderByQualifier`）。
- **P1**：`storage.retention.unit` / `partition.interval` 的非字符串值显式报错（`TestStorageRetentionUnitType` / `TestStoragePartitionIntervalType`）。
- **P1**：`counterpartID` 查找 `ID`（此前查小写 `id` 永远为空，relation 的 `join_column` 类型一致性实际未生效）；补 `TestEntityRelationJoinColumnTypeMismatch`。
- **P1**：枚举引用支持 `*data.enums.*` 指针（`enumUsages` / `scanEnumTypeRefs`），并改为读取 `source.column`；补 `TestEnumPointerUsage`。
- **P1**：实体返回的 computed `never_expose` 字段无法被 `return_columns` 裁剪，跨模块直接报 `query-sensitive-columns`；补 `TestEntityCoverageComputedSensitive`。
- **P1**：`values` 的键计入索引列提及（`exprText`），合法 insert 不再因“值表达式不含列名”被 `index-used-by-ref` 误拒；补 `TestQueryExprTextValueKeys`。
- **P1**：结构化谓词的 `param` 必须 non-nullable；可选过滤改用字符串表达式（`narg IS NULL OR col = narg`），堵住“谓词参数绕过 `query-param-nullable`”的缺口；补谓词 nullable 回归。
- **P1**：`storage.yaml` 顶层未知键、`engines.<name>.enabled` 非 bool、`supported_engines` 非字符串均报 `storage-doc`；补 `TestStorageDocShape`。
